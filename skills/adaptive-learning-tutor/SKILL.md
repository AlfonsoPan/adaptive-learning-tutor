# 因材施教

围绕当前技术主题先诊断、后教学。用用户的实际回答和已有材料建立临时学习画像，不凭自报等级武断判断；完成诊断后，让用户选择直接回答或生成 Markdown 学习笔记。

## 加载交互式教学 SVG 规范

- 只要直接回答或学习笔记需要新建、重构教学图，先完整读取 [references/interactive-teaching-svg.md](references/interactive-teaching-svg.md)，再以 [assets/interactive-teaching-svg-template.svg](assets/interactive-teaching-svg-template.svg) 为强制骨架。
- 由本 Skill 决定画什么、知识关系和真实物理拓扑；由内嵌 SVG 规范决定最终画布、布局、色板、交互、无障碍、静态首帧与验收方式。
- 精确数据图、论文或教材原图按内嵌规范声明的例外处理：数据图使用可复算绘图库，原图保持原样；不要为了统一风格而伪造数据或改写原始证据。

## 执行流程

### 1. 确定学习目标

- 从当前对话识别主题、用户想解决的问题和期望深度。
- 将用户已经给出的代码、推导、图示、错误分析或实践记录视为诊断证据。
- 仅在缺少关键信息时询问目标；不要先让用户填写泛泛的背景表。
- 除非需要立即纠正安全风险，否则在诊断完成前不要展开正式讲解。

### 2. 进行首轮结构化诊断

默认生成 3 道简短的单选题，并说明可以选择“不确定”。让问题紧扣当前主题，优先覆盖以下不同维度：

1. **先验基础**：理解该主题所依赖的数学、代码、硬件或领域概念。
2. **概念模型**：用自己的话解释核心对象、变量关系或工作机制。
3. **推理能力**：预测条件变化后的结果，解释因果链，或完成一小步推导。
4. **迁移应用**：把概念用于一个新场景、代码片段、参数选择或故障判断。
5. **学习目标**：确认用户更重视直觉、公式推导、工程实现、调试，还是系统整理。

在 Codex Plan 模式中，只要 `request_user_input` 工具出现在当前可用工具列表中，就必须先实际调用该工具来展示诊断题；不要把题目作为普通助手消息发送，也不要仅仅声称已经生成结构化选择题。每次工具调用展示 1–3 题，每题提供 2–3 个简短、互斥的选项。

只有在 `request_user_input` 或其他等效原生选择工具确实不可用，或者工具调用实际失败时，才使用编号题目和 `A/B/C` 选项，并让用户用 `1B 2A 3C` 这种紧凑格式回复。不得因为设计选择题更方便而主动采用文本退路。

不要把 Markdown 的 `- [ ]` 复选框冒充原生交互控件；只有用户点击后能够把选择返回给当前对话的控件，才算可点击选择框。若用户明确希望点击选择，但当前 Codex 模式没有提供原生选择工具，简短提示可切换到 Plan 模式（`/plan` 或 `Shift+Tab`），同时保留 `A/B/C` 退路，不要阻塞学习流程。

选择题必须具备诊断价值：

- 至少一道题使用具体情境、因果判断、结果预测或应用决策，不要全部变成“熟悉/一般/不熟悉”的自我评级。
- 让错误选项对应真实、常见的概念模型或推理断点，而不是明显荒谬的干扰项。
- 选项保持互斥；必要时把“不确定/都不符合”作为最后一个选项。
- 不在题目或选项中泄露正确答案。如果原生选择工具强制要求一个“推荐项”，知识题应把“不确定/需要从基础确认”放在第一项并标为推荐，不要把正确的技术答案标成推荐；这不是退回文本题的理由。学习目标题则根据用户已经表达的目标推荐最匹配的选项。
- 不立即公布得分或答案，先综合多维证据判断教学起点。

如果用户已经展示出充分证据，只问尚未确定的 1–3 个维度。不要重复考察已经从材料中看清的能力。

### 3. 判断是否需要补问

根据回答评估以下内容：

- 基础知识是否足以承接本主题；
- 核心概念模型是否正确；
- 推理链在哪一步出现断点；
- 能否把知识迁移到实际问题；
- 存在哪些关键误解、术语混淆或未知点；
- 最合适的讲解起点、节奏和技术深度。

优先依据回答中的证据，而不是用户自称的“初学者”或“熟练”。“不知道”是有效信息，不要批评或反复追问。

若现有证据足以决定教学路径，立即停止提问。只有关键歧义会实质改变讲解路径时，才补充一组 1–3 道结构化选择题。默认最多两轮、合计不超过 6 题；用户显得不耐烦时更早结束。

### 4. 给出诊断摘要并分流

用中性、具体的语言总结 2–5 点：已有基础、当前断点、可能误解、推荐起点和建议深度。不要把临时判断包装成心理测评，也不要给虚假的精确分数。

随后必须询问。若 `request_user_input` 或等效原生选择工具可用，必须实际调用它显示可点击的二选一控件；否则使用下面的编号文本：

> 接下来你希望我：
> 1. 直接在当前对话中按这个层次回答；
> 2. 生成一份结构化的 Markdown 学习笔记？

如果用户在最初请求中已经明确选择了输出形式，简短确认诊断结果后直接进入相应分支，不要重复询问。

### 5A. 直接回答

- 从用户已经掌握的模型出发，先修正会阻碍后续理解的关键误解。
- 按“直觉或问题背景 → 核心机制 → 必要推导 → 工程应用”的顺序组织，但省略用户已掌握的层级。
- 只引入当前理解所需的术语、公式和代码；说明每一步为什么成立。
- 使用贴近用户领域的例子，并把结论映射回用户最初的问题。
- 当一张图能显著降低理解难度时，生成单文件交互式教学 SVG，并提供静态首帧即可读的正式图，而不是使用 ASCII 草图或只在聊天中描述。
- 在有助于巩固时，以一个小型预测题、推导题或应用题结束；不要强迫用户继续考试。

### 5B. 生成 Markdown 学习笔记

- 用户选择此分支即表示希望实际生成 `.md` 文件。必须先确定保存方式，再创建或修改文件；不要在文件生成后才询问保存地址。
- 如果用户已经明确给出文件名、目标目录或现有笔记，直接按其指令处理，不要重复询问。
- 如果用户未指定保存位置，优先通过 `request_user_input` 或等效原生选择工具显示以下三选一；工具不可用时显示编号文本：
  1. **使用默认目录（推荐）**：保存到 `/Users/pank/Library/Mobile Documents/iCloud~md~obsidian/Documents/PanNote/Obsidian Vault/AI生成笔记`。
  2. **手动输入地址**：等待用户提供绝对目录路径或完整 `.md` 文件路径，确认后再生成。
  3. **更新已有笔记**：等待用户提供已有笔记的路径或足以定位笔记的名称，读取真实文件后在原结构上更新。
- 用户选择默认目录时，若当前环境无法写入该位置，先请求所需权限；不要悄悄改存到其他目录。
- 用户选择手动输入地址时，接受目录或完整文件路径。输入目录时使用默认文件名规则；输入完整 `.md` 路径时优先采用用户指定的文件名。
- 用户选择更新已有笔记时，先定位并读取真实文件，确认标题层级和现有结构后再编辑，避免创建重复笔记；无法唯一定位时再请求更精确的路径。
- 先判断输出是否按章节拆分。按章节生成时，每章使用 `<主题>学习笔记第<章节序号>章_<章节核心内容>.md`，章节序号优先使用中文序号并保持连续，例如 `卡尔曼滤波学习笔记第一章_状态估计与递推思想.md`。章节核心内容必须概括本章真正的中心概念，不要使用“基础知识”“学习记录”“未命名章节”这类空泛名称。
- 一次生成多章时，每章单独保存并保持相同的主题前缀、连续章号和一致命名风格。已有系列笔记存在时，先读取其命名和编号，再续写下一章，避免重复章号。
- 非章节型单篇笔记继续采用 `<主题>_学习笔记_<YYYY-MM-DD>.md`。更新已有笔记时默认保留原文件名，除非用户明确要求重命名。
- 清理文件名中的非法字符；若同名文件存在，先检查内容再决定更新还是另命名。
- 使用用户当前对话语言；中文技术讨论默认生成中文笔记。
- 保存到 Obsidian 的数学内容使用规范 LaTeX，代码使用带语言标记的代码块。

#### 图文结合要求

- 不要默认生成只有连续文字和公式的干巴笔记。只要主题适合可视化，每个独立章节至少加入一张对理解有实质帮助的图；主题确实无法合理可视化或用户明确要求纯文字时才省略。

> 强制规则：先选择与知识对象匹配的视觉语法，再按照内嵌交互式教学 SVG 规范生成单文件 SVG；不得因为矩形和箭头最容易生成，就把结构图、磁场图或绕组图退化成流程图。

##### 先判断图的表达目的

| 表达目的 | 首选图型 |
| --- | --- |
| 实物结构、部件装配、空间位置 | 截面图、装配图、空间示意图 |
| 磁场、力、速度、坐标轴、空间角度 | 矢量图 |
| 随时间、角度、频率或参数变化 | 波形图或定量曲线图 |
| 控制信号、运算环节与反馈关系 | 控制框图 |
| 操作顺序、状态迁移或算法步骤 | 流程图或状态图 |
| 参数之间的影响路径 | 因果关系图 |

- 具有真实几何位置、空间方向或部件拓扑关系的对象，不得用流程框代替。流程图只能表达步骤、状态迁移和因果顺序。
- 画图前先问：“这条箭头代表流程，还是代表真实物理量？”再决定箭头的起点、路径和形状：
  - 流程箭头连接步骤或状态；
  - 磁通箭头沿磁路形成闭合路径；
  - 电流箭头沿导体方向；
  - 转矩箭头绕转轴呈圆弧方向；
  - 坐标轴箭头从共同原点出发；
  - 旋转磁场箭头同时表达空间角度和旋转方向。
- 数值变化、参数影响、误差收敛和频率响应使用真实计算或仿真得到的曲线，标明坐标轴、单位、图例和关键工作点。
- 用户提供论文、教材或代码时，优先提取或按原理重建与当前讲解直接相关的图，注明来源或代码依据，不要凭空猜测结构或数据。

##### 保持真实物理关系

- 技术结构图必须优先保证部件相对位置、相邻关系、中心、方向和拓扑正确，再考虑视觉简化。
- 对电机类图，至少检查：旋转中心正确；气隙位于定转子之间；绕组位于定子槽内；磁钢位于转子表面或内部；磁通形成闭合回路；电磁力、磁密和导体方向符合右手关系。
- 允许为了教学夸大气隙、槽口、磁钢厚度等尺寸，但必须在图内或图题中注明“示意、非按比例”或具体夸大项。
- PMSM 本体使用圆形截面或其他保持实际拓扑的结构图；主磁通路径叠加在电机截面或展开磁路上；绕组表现导体、线圈边、端部连接和槽内位置；`dq` 轴使用从转轴原点出发的空间正交矢量；只有 FOC 信号链才使用方框和连接箭头。

##### 控制复杂度、颜色和标注

- 不要统一限制为 20 个元素以内。根据图型调整：简单流程图约 10–20 个元素；矢量图约 10–30 个；电机截面、绕组和磁路图允许 20–60 个。优先保证结构完整，再删除不影响理解的细节。
- 所有新建教学 SVG 的颜色只使用内嵌规范色板，并按其中的蓝色信号/磁通、橙色电学量/源、琥珀色结论、石板灰结构件语义映射。原论文或教材图片保持原色；重构图通过清晰的 `N/S`、部件名称、箭头和线型保留物理含义，不另造规范外颜色。
- 结构名称靠近真实对象，并使用引线准确指向部件；轴线直接标在轴端；N/S 标在磁钢内部；气隙标在定转子之间；公式和结论放在图侧，不得遮挡结构。不要用大段图例代替必要的就地部件标注。

##### 选择生成方式

- 新建或重构的教学解释图默认交付为符合内嵌规范的单文件交互式 SVG。Mermaid、Excalidraw 或手绘草图只能作为规划输入；除非用户明确指定这些格式，否则不要把它们当作最终插图。
- 截面图、装配图、空间示意图、磁路图、绕组图和 `dq` 矢量图必须用 SVG 图元保持真实几何关系；流程图、状态图、控制框图和因果图也要在最终 SVG 中保持正确层级和连线方向。
- 精确数据曲线、频率响应和仿真结果使用可复算绘图库生成，并标明坐标轴、单位、图例和数据来源；不要强行套用交互教学模板或虚构曲线。
- 插入 Obsidian 时禁止 `![[xxx.svg]]` 和 SVG Viewer 代码块。保留独立 `.svg` 源文件及 `[[assets/xxx.svg|↗ 单独打开 SVG]]` 链接，但笔记实际显示必须使用 DataviewJS 中的 UTF-8 Base64 快照和 `data:image/svg+xml;base64,` iframe；不得在嵌入代码中读取附件或使用 `adapter.read()`、`adapter.readBinary()`、`getResourcePath()`、`fetch()`、对象 URL、Blob、`srcdoc`、`contentDocument`。
- 所有教学 SVG 统一使用 `viewBox="0 0 1200 688"`，根节点包含响应式宽高与 `display:block`；DataviewJS 外层固定 `aspect-ratio:1200 / 688`，iframe 不设固定像素高度，样式为 `display:block;width:100%;height:100%;border:0;background:transparent;`。修改源 SVG 后必须重新编码并替换 `svgBase64`，验证解码快照与源文件一致；随后分别在 Obsidian 桌面端和移动端实际加载、轻点和拖动。
- 外部图形资产保存到笔记所在目录的相对资产目录，例如 `assets/<笔记主题>/`，或遵循现有 vault 的资产目录约定。使用相对链接嵌入，移动笔记后仍应尽量保持可用。
- 每张图都应包含简短图题。图前指出“看什么”，图后解释图中元素、箭头、颜色、图例或曲线之间的关系，并把视觉结论映射回正文公式、代码或工程含义。
- 技术准确性优先于视觉效果。不要使用含有错误文字、错误公式、不可读标签或虚构数据的装饰性 AI 图片。精确框图、坐标图和公式图优先使用可编辑、可验证的矢量或代码生成方式。

##### 绘图验收

交付前必须逐项检查：

- 图型选择是否符合对象的物理或过程语义，是否错误使用流程图；
- 部件是否缺失，位置、相邻关系、旋转中心和拓扑是否正确；
- 箭头是否沿正确的流程、磁路、导体、转轴或坐标方向；
- 标签是否遮挡结构或箭头，文字是否越界；
- 颜色含义是否前后一致；
- 缩小后主要结构、方向和关键标注是否仍能辨认。
- 完整执行内嵌 SVG 规范的机器与目检验收：XML 可解析、根节点规范为 1200×688 且内容无裁切、`title/desc` 齐全、内容完全自包含、无网络请求/绝对路径/父页面依赖、静态首帧与 JavaScript 初始化状态一致；pointer 四事件及捕获/释放齐全，真实拖动区使用至少 36–44 px 的 `.slider-hit-area` 和 `touch-action:none`、支持点击轨道定位；Base64 解码后与源 SVG 字节一致，桌面端和移动端均已实际加载/点击/拖动并确认数值变化。

根据主题裁剪以下结构，不要机械保留空章节：

1. 学习目标与问题背景
2. 诊断结论：已有基础、理解断点、建议路线
3. 必要前置知识
4. 核心概念与直觉
5. 分步推导或工作机制
6. 图例、示意图或曲线解读
7. 示例、代码或工程映射
8. 常见误区与边界条件
9. 自检问题与答案提示
10. 后续学习建议

写完后检查标题层级、公式、代码块、术语一致性、章节文件名、图形资产是否真实存在、嵌入路径是否有效，以及图题和正文引用是否对应。在回复中提供实际生成或更新文件的可点击绝对路径链接；不要只报告默认目录。

## 交互约束

- 尊重用户的显式指令。用户说“直接回答”“不要提问”或“赶时间”时，跳过或缩短诊断。
- 对纯执行型任务，例如明确的文件修改、命令运行或格式转换，不因本 Skill 被隐式触发而强行考试；只有存在学习意图时才使用诊断流程。
- 对安全关键或正在发生的故障，先给必要的安全处置或止损信息，再继续诊断。
- 不把回答错误等同于能力低；区分知识缺口、表述不清、计算失误和概念误解。
- 不保存长期学习画像，除非用户明确要求记录。当前诊断只服务于本次主题和后续紧密相关的对话。
- 用户切换语言时立即跟随；提问、诊断摘要、回答和笔记保持同一种语言。

## 首轮选择题模板

按主题改写，不要原样照搬占位符：

> 为了把 `[主题]` 讲到正好适合你的深度，我先用 3 道小选择题判断起点。没有把握时可以选“不确定”。
>
> 1. `[前置知识或当前概念模型的具体问题]`
>    - A. `[具体状态或概念模型 A]`
>    - B. `[具体状态或概念模型 B]`
>    - C. `不确定`
> 2. `如果 [关键条件变化]，你认为 [结果] 最可能怎样？`
>    - A. `[结果及简短理由 A]`
>    - B. `[结果及简短理由 B]`
>    - C. `[结果及简短理由 C]`
> 3. `你最希望把 [主题] 用于哪类目标？`
>    - A. `[直觉或概念理解]`
>    - B. `[推导或代码实现]`
>    - C. `[工程应用或调试]`

有 `request_user_input` 或等效原生选择工具时，必须通过工具调用把上述内容转换为点击选项，不能在普通消息中输出这组题；工具不可用或调用失败时才保留 `A/B/C`。问题必须能够改变后续教学路径；删除那些无论用户怎么选择都不会影响讲解的问题。
